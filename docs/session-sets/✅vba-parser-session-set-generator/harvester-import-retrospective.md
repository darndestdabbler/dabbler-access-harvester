## Cross-cutting themes

- **Verification cost is driven by ambiguity, not raw complexity.** The Session 1 plan was the most expensive session ($1.98 across 3 rounds) because of internal inconsistencies and unresolved ambiguity in its findings/dispositions, not because plan-authoring is technically harder than enrichment integration. Front-loading internal-consistency discipline is the single highest-leverage cost lever.
- **Calibration consistently overshot toward Opus on mechanical sessions.** Three of six sessions (50%) used Opus where Sonnet@medium was both recommended and adequate. The default-to-Opus reflex must be deliberately countered in Session 4's playbook.
- **The Promote-Lessons-to-Conventions feedback loop earns its keep.** Five Conventions and two Harvester-Specific Lessons emerged from the import set, each preventing a recurrence of a specific failure mode. The Step 9 review (post-notify) is structurally cheap and structurally important.
- **Cross-provider verification cannot be replaced by self-disclosure.** Session 6's `validate_against_yaml.py` finding was flagged Major even though the issue was explicitly disclosed in the verification prompt — the verifier rightly judged that disclosure does not immunize a real correctness gap visible to a fresh reader. Plan accordingly: disclose adjacent-but-unchanged code so the verifier doesn't hallucinate it missing, but do not assume disclosure makes a real defect acceptable.
- **Cost estimates should anchor on observed actuals, not provider pricing.** Provider list pricing under-predicts true session cost because it does not model verifier rounds, escalations, or the `documentation`-vs-`summarization` Gemini-400 retry path.
