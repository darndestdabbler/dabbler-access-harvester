## Feature 1: Parser Pipeline + Error Recovery

### Scope

Error-tolerant parser per Phase 2.2 of the plan. Recovery strategy specifics (sync points, lossy-parse fallback) are Session 1 elaboration; the shape commitment here is "errors are AST-level annotations, not exceptions, and parsing produces a partial AST plus an error list for any input."

### Standards

- Real Access databases contain malformed VBA (commented-out code that lost its comment marker, half-finished refactorings). Recovery must be robust on these inputs, not just on textbook-correct VBA.
- Errors are AST-level annotations, not exceptions. Downstream consumers read errors from the parser output, never via try/catch.

## Feature 2: AST Shape

### Scope

Immutable AST node hierarchy: `Module`, `Procedure`, `Statement` variants, `Expression` variants, `Declaration`, `Reference`. Visitor infrastructure walks the parse tree producing AST. Transformations produce new trees, never mutate.

### Standards

- AST shape is the contract every later parser/resolver child set depends on. Bias toward shape stability — even "obviously cleaner" rewrites in #7 onwards require explicit justification.
- Per `project-guidance.md` → VBA Parser Strategy, "unresolvable constructs are explicit, not silent." Parser-level analogue: AST nodes carry provenance metadata when their shape is degraded by error recovery.

## Feature 3: Position Tracking

### Scope

`SourceLocation` (file, line, column) and `SourceRange` (start + end) types. Every AST node and resolved declaration carries one. Transformations preserve or compose ranges; ranges never go null.

### Standards

- The downstream consumer is an AI agent that points back to source for review and migration documentation. Missing locations defeat that workflow.

## Feature 4: Preprocessor Pass-Through

### Scope

`#If`/`#Else`/`#End If`/`#Const` directives parsed and preserved in AST as opaque blocks. No evaluation in this set — evaluation is deferred to `resolver-references-and-with-blocks` (#8) or later, when host context is established. Authors the paired preprocessor fixture (`13-preprocessor.bas` + `13-preprocessor.expected.json`).

### Standards

- Per Phase 2.5 of the plan: "In Phase 2, parse but don't evaluate directives — preserve them in the AST as opaque blocks."
