### Action Query coverage

The new rules Q8, Q9, and Q10 improve coverage for non-SELECT queries. Rules Q8 and Q9 correctly handle the primary DML action queries (Delete, Update, Append, MakeTable) by classifying them as `StandaloneUtility` when invoked programmatically and `PossiblyUnused` otherwise. The priority note clarifying that Q8/Q9 supersede Q7 is essential and correct.

However, rule Q10 contains a misclassification. While it correctly classifies Data Definition (DDL, TypeCode 6) and Pass-through (TypeCode 128) queries as `StandaloneUtility`, it incorrectly groups Union queries (TypeCode 64) into the same category. A Union query is a type of SELECT query that combines result sets; it does not perform a data modification "action" in the same vein as DDL or DML queries. Its purpose is data retrieval and presentation, making it functionally equivalent to a `Reporting` query. Other rules (Q2, Q3) which could correctly classify it as `MainDataEntry` or `Reporting` will not fire because they are scoped to `QueryTypeCode = 0`. Therefore, all Union queries will be misclassified as `StandaloneUtility` by rule Q10.

### Soft-prereq degradation

The updated Section 11 now accurately describes the system's behavior when query KB files (from the `harvester-body-and-query-sql` tool) are absent. It correctly states that the `QueryTableReferenceReader` will emit no signals, but other signal collectors that rely on different IR files (like `RecordSourceCollector`) will function normally, allowing queries to still be classified by rules like Q2, Q3, or Q7.

Crucially, the document clarifies that the `QueryReferencesNoTables` question is only generated by rule Q6 when SQL is present and lacks table references. This prevents the system from incorrectly flagging every query with a question mark when the prerequisite harvester has not been run, which is the correct and desired behavior for graceful degradation.
